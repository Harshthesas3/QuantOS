# Contributing to QuantOS

Thank you for your interest in improving QuantOS.

## Before You Start

- Read [LICENSING.md](LICENSING.md) to understand what contributions may be included in the repository.
- Keep contributions aligned with the Community Edition license unless you are working under a commercial agreement.

## Development Workflow

1. Create a branch for your change.
2. Make the smallest clear change that solves the problem.
3. Run the relevant checks before opening a pull request.

Recommended checks:

- `npm run typecheck`
- `npm run lint`
- `npm run build`

## Code Quality

- Keep changes focused and easy to review.
- Match existing patterns and naming.
- Include tests when you change behavior.
- Avoid large unrelated refactors.

## Pull Requests

- Describe what changed and why.
- Mention any user-facing impact.
- Note any follow-up work that remains.

## Licensing of Contributions

By submitting a contribution, you confirm that you have the right to submit it and that it may be used under the project’s licensing model.

If you are contributing on behalf of an organization, make sure you have permission to do so.
